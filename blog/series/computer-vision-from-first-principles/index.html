Computer vision from first principles — pixels to understanding, the foundations beneath the Multimodal AI series. Images as Data — Why Computer Vision Is Hard

Humans see so effortlessly that it's easy to forget vision is one of the hardest problems in computing. To a computer an image is just a grid of numbers, and turning those numbers into "that's a cat" requires bridging an enormous gap between raw pixels and meaning. This series builds computer vision from first principles — from pixels to classical methods to the deep learning that finally cracked it — and it starts with why the problem is so deceptively hard.

To a computer an image is just a grid of numbers, and turning those into 'that's a cat' means bridging the semantic gap — made brutal by viewpoint, lighting, scale, occlusion, and intra-class variation. Why vision defeats hand-written rules and is fundamentally a learning problem.

Classical Computer Vision — Features Before Deep Learning

Before neural networks, computer vision spent decades building an ingenious toolkit: detect edges, find corners, describe local patches, match features across images. These classical methods are no longer state of the art for recognition, but they're far from obsolete — they still power real systems, they illuminate what deep learning automated, and understanding them makes you a better vision engineer. This post covers how vision worked before deep learning, and why it still matters.

Before neural networks, vision hand-engineered features: edges, corners, invariant descriptors (SIFT). These still power matching, panorama stitching, and 3D/SLAM — and reveal exactly what CNNs later automated. Their ceiling on recognition is what the deep-learning breakthrough overcame.

Convolutional Neural Networks — The Breakthrough That Cracked Vision

The convolutional neural network is the architecture that finally solved computer vision — and it did so with an idea as elegant as it is powerful: slide a small learnable filter across the image, everywhere, looking for patterns. CNNs automated the feature engineering that classical vision did by hand, learning a hierarchy from edges to objects directly from pixels. This post explains how convolution works and why it was exactly the right inductive bias for images.

The CNN solved vision by learning features instead of hand-designing them. Convolution slides a small learnable filter everywhere — local connectivity and parameter sharing give translation invariance for free — and stacking layers builds a hierarchy from edges to objects. The right inductive bias for images.

CNN Architectures — How Networks Got Deeper and Better

Once convolution proved it could crack vision, the race was on to build better CNNs — and the story of how they improved is a compact lesson in deep learning itself. From AlexNet to VGG to ResNet, each landmark architecture solved a specific problem that was blocking progress, and the solutions (depth, small filters, skip connections) became foundational ideas used far beyond vision. This post traces that evolution and the principles it taught.

From AlexNet (which launched deep learning) to VGG (small filters, deep) to ResNet (skip connections that made very deep networks trainable), each landmark solved a specific blocker. ResNet's residual connection generalized everywhere — including every transformer block — so the arc is a compact lesson in deep learning itself.

Object Detection and Segmentation — Beyond "What Is This?"

Classifying a whole image as "cat" is only the beginning of computer vision. Real applications need to know where the cat is, how many objects there are, and sometimes exactly which pixels belong to each one. Object detection and segmentation answer those harder questions, and they power self-driving cars, medical imaging, and photo editing. This post covers the main vision tasks beyond classification and how they build on the CNN foundation.

Real vision needs more than 'what is this?' — the task hierarchy runs classification → detection (bounding boxes) → semantic segmentation (per-pixel) → instance segmentation. How one-stage (YOLO) vs two-stage detectors and encoder-decoders (U-Net) build on the CNN backbone, powering self-driving and medical imaging.

Vision Transformers — When Attention Came for Images

For a decade, convolution was synonymous with computer vision. Then the transformer — the architecture that revolutionized language — was applied to images, and the vision transformer showed that attention could match or beat CNNs given enough data. It's a profound shift: the same architecture now underpins both language and vision, enabling the multimodal models that see and read at once. This post explains how transformers handle images and what their rise means.

The vision transformer treats an image as a sequence of patches and runs a standard transformer, giving global context immediately. The deep trade-off (CNN inductive bias vs ViT learning from data — ViTs win at scale) and the big consequence: one architecture now unifies vision and language, enabling multimodal AI.

Transfer Learning and Data — How Vision Actually Gets Built

Almost nobody trains a computer-vision model from scratch — and if you're trying to, you're probably doing it wrong. The real practice of vision is transfer learning: take a model pretrained on millions of images, adapt it to your task with a fraction of the data. This, plus smart data strategy, is how vision gets built in the real world, and it's the single most practical thing to understand about applying computer vision. This post is about how it's actually done.

Almost nobody trains vision models from scratch — the real practice is transfer learning: adapt a pretrained model with a fraction of the data. Feature extraction vs fine-tuning (chosen by data size), and the data realities (labeling cost, representativeness, augmentation) that actually decide a vision project.
