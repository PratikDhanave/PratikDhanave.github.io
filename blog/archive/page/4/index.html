Artifact Evolution: The Generate–Evaluate–Refine Loop

The least philosophical form of self-evolving AI is also the one with the hardest results to argue with: hold the model fixed, hold the harness fixed, and evolve the artifact — the program, the schedule, the mathematical construction — through thousands of generate-evaluate-refine rounds. This post dissects that loop: why it's evolutionary computation with the mutation operator replaced by a language model, why the evaluator is the entire ballgame, and what changes when the LLM is both the operator and, increasingly, the optimizer.

Artifact evolution is evolutionary search with an LLM as the mutation operator — population, generator, evaluator, selector — where the LLM contributes semantically valid, evidence-driven edits and the evaluator contributes everything else. Offline loop, mechanical feedback, externally checkable results: the honesty standard for the rest of the map.

Retrieval Memory — Vector Stores, Scoring, and the Art of Remembering the Right Thing

The standard answer to agent memory is "embed it and put it in a vector store" — and it's half right. Semantic search over past experience is genuinely the workhorse of episodic recall. But raw similarity is a weak model of what "relevant memory" means: similar is not important, recent, or true. The difference between a memory system and a junk drawer with an embedding index is the scoring, filtering, and hygiene this post covers.

Memory retrieval is not document RAG: the store is self-generated, time-sensitive, and self-contradicting. Score on relevance x recency x importance, enforce write-side hygiene — self-contained memories, dedupe at the door, attached structure — and inject under a budget with provenance labels so memories are weighed, not absorbed.

From U-Net to Diffusion Transformer — The Architecture Underneath the Denoiser

For the first years of diffusion, "the model" meant a U-Net — a convolutional hourglass borrowed from medical image segmentation. Then the same migration that had already run through NLP and vision ran through generation: replace the handcrafted spatial architecture with a plain transformer over patch tokens, and let scale do the work. The Diffusion Transformer (DiT) is now the backbone of the frontier image and video systems — and the reasons why are a case study in what architectures are actually for.

The denoiser was a U-Net — convolutional hourglass, skip connections, interleaved cross-attention — until the Diffusion Transformer re-answered the same requirements generically: patchify the latent, run a standard transformer, condition via adaptive layer norm. The real win is economic: LLM-style scaling curves, inherited infrastructure, and spacetime patches that set up video.

Pricing Models in Code — The Catalog Is Data, Not Constants

Every pricing page looks simple: three tiers, a slider, maybe "contact us." The code behind a pricing page that can evolve is anything but — because pricing changes faster than software, old customers keep old deals, and the moment a price lives as a constant in application code, every experiment becomes a deploy and every grandfathered customer becomes an if-statement. The foundational move of billing engineering is modeling the catalog as versioned data.

Flat, per-seat, graduated vs volume tiers (not the same thing), usage, hybrids — one abstraction: price is versioned data mapping quantity-over-a-period to an amount. Immutable price versions make grandfathering default behavior and invoices re-derivable; application code never holds an amount.

Drift and Adaptation — Defending Against an Adversary Who Read Your Model

Ordinary ML drift is weather — the world changes and models age. Fraud drift is war — the distribution shifts precisely because you deployed, as attackers probe the new boundary and route around it. A fraud system's long-run performance is therefore determined less by any single model than by its adaptation loop: how fast drift is detected, how fast a response ships, and how safely the response is validated against labels that haven't arrived yet. This post builds that loop.

Against an adapting adversary the system is the loop: detection cascaded by speed (input drift, score drift, proxy labels, chargeback truth), responses laddered by cost (expiring tactical rules in minutes, threshold posture, cadence-plus-trigger retrains, shadow challengers), validation staged around label delay.

Simulating Time — Testing the Behavior That Only Happens Later

Some of the most consequential code in any system runs when nobody is deploying: renewals at midnight, trials expiring on day 14, tokens timing out, retries backing off, data retention sweeping on schedule. Testing it by waiting is absurd; testing it by mocking one clock call is fragile; testing it properly means making time itself a controllable dependency of the system under test — and that choice, it turns out, improves the architecture even before it improves the tests.

Time becomes testable as an injected dependency: audit its disguises (timeouts, backoffs, TTLs, expiries), drive schedules through clock-driven executors, simulate by scope — discrete-event clocks in-process, one-clock slices across services, simulation as a product feature for platforms. Calendar edges are shared fixtures.

Conversation Memory and Compaction — Surviving the Long Session

The first memory problem every agent hits is the humblest: the conversation itself outgrows the window. Tool outputs pile up, reasoning accumulates, and somewhere past the first hour the agent must start forgetting parts of its own session — the only question is whether it forgets with judgment or at random. Compaction is where memory engineering starts, and it's harder than it looks because the thing doing the summarizing is the thing that needs the summary.

The strategy ladder — buffer, sliding window, selective eviction, compaction — and why the top rung needs engineering: a preservation contract for what survives verbatim, structured rolling summaries, boundary-triggered timing, and the architectural rule that compaction should demote to episodic storage, never delete.

Conditioning and Classifier-Free Guidance — How Text Steers the Image

Everything so far generates an image — any image the training distribution contains. A product needs the image you asked for. Conditioning is how a prompt gets wired into every denoising step, and classifier-free guidance — a two-line trick discovered almost apologetically — is the single knob that most determines whether the output actually obeys the prompt. The famous "CFG scale" slider in every image UI is this post.

Conditioning wires the prompt into every denoising step via text encoders and cross-attention — but the honest conditional distribution follows prompts too loosely. Classifier-free guidance fixes it: co-train an unconditional mode, then extrapolate the difference at sampling. One knob for fidelity vs diversity, 2× cost, and negative prompts for free.
